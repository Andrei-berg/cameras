# Концепция интерфейса — ГОРМОСТ Мониторинг камер

Ориентиры: лучшие практики компаний-лидеров в категории видеонаблюдения и операционного ПО
(исследование 2026-06-11).

## Кто в топе и что мы у них берём

| Компания | Положение | Что заимствуем |
|---|---|---|
| **Verkada** (Command) | №1 мирового рынка VSaaS | Карта ↔ список объектов бок-о-бок с синхронной фильтрацией; инцидент как контейнер (видео-доказательства + заметки + автоотчёт); статусные плитки |
| **Rhombus** | ближайший конкурент Verkada | Единая консоль для всего парка без переключения инструментов; лёгкость и скорость интерфейса |
| **Eagle Eye Networks** | открытая cloud-VMS платформа | Открытость к чужому железу (у нас KSVD + Интеллект — двухвендорная среда, как у них) |
| **Linear** | эталон операционного UI | Плотность без перегруза: «каждый видимый элемент зарабатывает своё место»; ⌘K-палитра; сохранённые виды; клавиатурные сценарии |
| **Datadog / Grafana** | эталон мониторинговых дашбордов | Сводка = тренды и отклонения, а не просто числа; heatmap по участкам |

Важное отличие: наша система — **операционный слой над VMS** (реестр + инциденты + ремонты),
а не просмотр живого видео. Видео остаётся в KSVD/Интеллект; мы можем давать deep-link на RTSP/KSVD.

## Принципы

1. **Статус прежде всего.** Везде, где упоминается камера/объект — цветовой статус виден без клика.
   Красный = не работает, янтарный = в ремонте, зелёный = работает.
2. **Плотность Linear, а не «воздух» маркетинговых SaaS.** Диспетчер открывает систему десятки раз
   за смену — оптимизируем на скорость взгляда, не на красоту скриншота.
3. **Роль определяет стартовый экран** (стандарт 2026: role-based views по умолчанию):
   - **Диспетчер** → неработающие камеры + открытые инциденты, кнопка «зарегистрировать инцидент» в один клик;
   - **Инженер** → назначенные ему ремонты, маршрут на день, карта;
   - **Руководитель** → KPI: доля работающих, динамика по участкам, просроченные ремонты;
   - **Админ** → пользователи, импорт реестра, справочники.
4. **Один инструмент.** Как у Rhombus: реестр, карта, инциденты, отчёты — без переключения систем.
5. **Клавиатура и поиск.** ⌘K-палитра (паттерн Linear): «найти камеру», «создать инцидент»,
   «перейти на участок» — из любого экрана.

## Структура

```
┌ Шапка: лого · Главная · Камеры · Инциденты · Карта · Отчёты · [⌘K поиск] · профиль
│
├ /dashboard   Оперативная сводка (роль-зависимая)
│              плитки статусов → тренд за 30 дней (DailySnapshot) → heatmap участков
├ /cameras     Реестр: фильтры + сохранённые виды («Мой участок», «Сломанные KSVD»)
├ /cameras/[id] Карточка: техданные · история инцидентов · кнопка «Инцидент» · ссылка в KSVD
├ /incidents   Лента инцидентов: статусная доска (open → in_repair → resolved)
│              инцидент = контейнер: причина · фото · заметки · визит специалиста · автоотчёт
├ /map         Yandex Maps + кластеризация; карта ↔ список синхронно (паттерн Verkada Sites)
│              клик по кластеру = фильтр списка; цвет кластера = худший статус внутри
└ /admin       Пользователи · импорт Excel · справочники участков
```

## Дизайн-система (заложена в Phase 2)

- Шрифты: **Golos Text** (UI, кириллица) + **JetBrains Mono** (IP, порты, ключи KSVD, счётчики)
- Токены в `globals.css` через `@theme`: canvas/surface/ink/line/accent/ok/fail/warn
- Палитра: светлая «индустриальная сталь», сигнальные статусные цвета
- Компоненты: StatusBadge, плотные таблицы 50/стр, фильтры GET-формой (работают без JS)
