# Идеи из проекта Gormost → Мониторинг камер

Источник: https://github.com/Andrei-berg/gormost (планирование работ тоннеля).
Это **дельта-список**: только то, чего в cameras ещё нет. Каждый раздел самодостаточен —
можно сказать Claude Code «реализуй раздел N» и дать ссылку на файл-образец в gormost.

Архитектурное отличие, которое надо учитывать при переносе: gormost — клиентские
компоненты + RPC (`/api/db`), cameras — серверные компоненты + Prisma + server actions.
Паттерны переносим, код — адаптируем.

---

## 1. Тёмная тема (приоритет: высокий)

Cameras уже на токенах `@theme` в `globals.css` — значит тёмная тема = один блок
переопределений + переключатель. Это дёшево именно потому, что дизайн-система уже правильная.

**Как в gormost:**
- Класс `.dark` на `<html>`, `darkMode: 'class'`
- Inline-скрипт в `<head>` ставит класс ДО первой отрисовки — нет мигания
  (`gormost: src/app/layout.tsx`, 3 строки)
- `ThemeContext` + localStorage (`gormost: src/lib/ThemeContext.tsx`, 48 строк)
- Тема по умолчанию — тёмная (диспетчеры работают ночью!)

**Адаптация под cameras:** добавить в `globals.css` блок
`html.dark { --color-canvas: #0f1620; --color-surface: #18222e; --color-ink: #e8edf2; … }` —
все компоненты уже пишут `bg-surface text-ink`, перекрасятся сами. Сигнальные цвета
(ok/fail/warn) для тёмного фона взять ярче: `#3FB950 / #F85149 / #F0A500` (палитра gormost).

**Урок gormost (не повторять ошибку):** не делайте `isLight ? … : …` в JS и не
используйте сырые цвета в компонентах — только токены. В gormost пришлось выпиливать
188 таких тернарников.

## 2. Правило-движок системных тревог (приоритет: высокий)

В gormost есть `fetchSystemAlerts()` (`src/lib/api.ts`) — функция, которая по данным
вычисляет тревоги ПО РОЛИ с эскалацией по времени: «план не подан, до совещания 2ч —
warning, после 15:00 — critical».

**Перенос в cameras** — серверная функция `getAlerts(role)` рядом с дашбордом:
- камера не работает **> N дней** без инцидента → critical «5 камер сломаны, инцидент не заведён»
- инцидент в `open` > 24ч без назначения → warning
- инцидент в `in_repair` > 7 дней → critical «просроченный ремонт»
- доля работающих на участке < 80% → warning по участку
- для инженера — только его ремонты; для руководителя — сводно

Рендер — баннеры над дашбордом (образец: `gormost: src/components/AlertBanner.tsx`,
красный/янтарный, кликабельные, ведут на отфильтрованный список).
Это превращает дашборд из «снимка состояния» в «список того, что требует действия».

## 3. Живые счётчики-пилюли в навигации (приоритет: высокий)

В gormost главная страница показывает на каждой карточке панели живую пилюлю:
«9 сломано», «4 на согл.» — с цветом по серьёзности и **русской плюрализацией**
(`gormost: src/app/page.tsx` — функции `liveMeta()` и `plural()`).

**Перенос:** в `DashboardNav.tsx` — бейджи на пунктах: Инциденты **(7)**,
Камеры **(12 ✗)**. В серверном layout это один Prisma-запрос. Пульсирующая точка
у критичных значений — анимации `chip-pulse-red/amber` готовы в
`gormost: src/app/globals.css` (@keyframes chipPulse*).

## 4. Канбан-доска инцидентов (приоритет: средний)

DESIGN.md cameras уже упоминает «статусную доску» — в gormost она реализована:
`src/components/KanbanBoard.tsx` (общий, переиспользуется 3 панелями) на `@dnd-kit`:
колонки по статусу, drag-and-drop меняет статус, счётчики в заголовках колонок.

**Перенос:** `/incidents` board-вид: open → in_repair → resolved. Карточка = камера,
объект, давность (см. §7), исполнитель. Drag = server action смены статуса.
Это единственное место, где cameras понадобится клиентский компонент с данными —
паттерн обёртки: серверная страница грузит данные, передаёт в `'use client'`-доску.

## 5. Печатные формы из HTML (приоритет: средний)

В gormost печатные документы генерируются как автономный HTML со стилями
`@page`/`break-inside` и открываются в новом окне на печать —
`gormost: src/components/head/PlanTaskSheetModal.tsx` (функция `generateSheetHTML`):
Times New Roman, шапка организации, таблица с пустыми строками «на дописать ручкой»,
подписи. Никаких PDF-библиотек.

**Перенос:** «Акт о неисправности камеры» и «Наряд на ремонт» из карточки инцидента —
один клик, готовый к печати А4. Для гос-учреждения печатные формы = ежедневная реальность.

## 6. Срез «было — стало» за смену/сутки (приоритет: средний)

У cameras запланирован DailySnapshot (тренд 30 дней). Дополнение из gormost — блок
«за последние 24ч» на дашборде: **+3 сломалось, −5 починили, 2 новых инцидента**
(дельты, не абсолюты — паттерн Datadog, в gormost так устроен `ChiefStats`/`PlanStats`).
Считается сравнением текущего состояния с последним снапшотом.

## 7. «Давность» как первоклассный сигнал (приоритет: лёгкая победа)

В gormost транспорт подсвечивает технику, сломанную **≥ 3 дней** («3 долго в ремонте» —
`src/app/transport/page.tsx`, `brokenStale`), а тревоги показывают «Ожидание 2ч».
**Перенос:** в списках инцидентов — возраст инцидента крупно и цветом
(зелёный < 24ч, янтарный < 3д, красный дольше); сортировка по умолчанию — старые сверху.

## 8. Статус-бар внизу экрана (приоритет: косметика)

Монospace-полоска внизу: зелёная точка · название системы · участок · число камер
онлайн · время (`gormost: src/app/page.tsx`, низ). Атмосфера диспетчерского пульта,
дёшево, добавляет «живости».

## 9. Подсказки «что дальше» и гайд-туры (приоритет: низкий, когда появятся пользователи)

`WhatNextBanner` — контекстная подсказка по роли и состоянию данных(«У вас 3 инцидента
без исполнителя → [Назначить]»), `GuidedTour` — обучающий тур по панели при первом входе
(`gormost: src/components/help/`). Снимает вопросы при вводе системы в эксплуатацию.

## Процессные практики gormost (применить с первого дня)

1. **CLAUDE.md в корне** с правилами: build перед коммитом, тонкие page.tsx,
   куда класть компоненты, что нельзя трогать. Образец — gormost/CLAUDE.md.
2. **Тесты на бизнес-логику до UI** (Vitest): в cameras это правила тревог (§2),
   расчёт дельт (§6), маппинги статусов при импорте Excel.
3. **Журнал действий**: таблица changelog (кто/что/когда) с первого дня — в gormost
   `logAction()` зовётся из каждой мутации. Для инцидентов это будущая «история
   инцидента» бесплатно.
4. **Ловушка Tailwind**: модификаторы непрозрачности НЕ кратные 5 (`bg-white/3`)
   не генерируются без расширения шкалы `opacity` в конфиге — gormost наступил,
   чинили отдельным коммитом.

## Что НЕ переносить

- Glassmorphism / blur — конфликтует с «индустриальной сталью» и плотностью Linear,
  выбранными в DESIGN.md. Тёмная тема cameras должна быть плоской и плотной.
- RPC-слой `/api/db` — у cameras серверные компоненты + Prisma, это лучше.
- Эмодзи как иконки — в cameras их нет, и это правильно.
